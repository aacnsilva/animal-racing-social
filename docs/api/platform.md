# Platform APIs (v1)

Auth, race card & history, daily reward, admin, notifications and API
conventions. Betting semantics: [`betting-design.md`](./betting-design.md).

## 1. Auth: Google & GitHub only

OAuth 2.0 / OIDC with PKCE. No passwords.

```
GET  /v1/auth/{provider}/start?redirect=/…      provider = google | github → 302 to provider
GET  /v1/auth/{provider}/callback               → sets session, 302 to redirect
POST /v1/auth/refresh                           → rotates access token
POST /v1/auth/logout
GET  /v1/me                                     → { userId, displayName, avatarUrl, providers[], createdAt }
PATCH /v1/me                                    → { displayName, avatarUrl }
POST /v1/me/providers/{provider}/link           → link a second provider to the same account
```

- Session: short-lived access JWT (15 min) + httpOnly refresh cookie (30 d,
  rotated). The SSE stream authenticates with the same cookie.
- Identity key is `(provider, providerSubject)`, **never email** (GitHub emails
  can be private or change).
- **`userId` is generated by us and shard-aware** (64-bit: timestamp |
  logical shard | sequence). The social layer will shard Postgres by user,
  so we fix the ID format now even though betting runs on one database at first.

## 2. Race card & history

```
GET /v1/schedule?from=&to=&species=&class=     → upcoming races (SCHEDULED/OPEN/LOCKED/LIVE), ≤ 24 h ahead
GET /v1/races?status=FINISHED&from=&to=&species=&venueId=&animalId=&cursor=   → past races
GET /v1/races/{raceId}/result                  → official order, asRun, finish times,
                                                 lap leaders, incidents, payouts per market,
                                                 seed, replay: { available, expiresAt }
GET /v1/venues/{venueId}/history?cursor=       → past races at a venue
```

Past races stay listable forever; full tick replays follow `REPLAY_RETENTION_HOURS`.

## 3. Daily reward (claim)

```
GET  /v1/me/rewards/daily   → { claimable, amount: 50, nextClaimAt, streak }
POST /v1/me/rewards/daily   → 200 { amount, balance } | 409 ALREADY_CLAIMED
```

- One claim per UTC day. Ledger `DAILY_GRANT` with `refId = userId:YYYY-MM-DD`,
  so double-clicks and retries are harmless without an idempotency key.
- Streak is tracked for display only; the amount stays 50 until we decide otherwise.

## 4. Admin API

`/v1/admin/*`, role `ADMIN` (granted manually to specific userIds). Every
call writes an audit log entry (`admin.audit` topic: who, what, before/after).

| Area | Endpoints |
|---|---|
| Programme | `GET/PUT /admin/programme` (races/hour, class mix, species rotation) · `POST /admin/races` (schedule one-off) · `POST /admin/races/{id}/cancel` (all bets VOID) |
| Markets | `GET/PUT /admin/market-templates/{class}` · `POST /admin/markets/{id}/suspend` · `/resume` · `/void` |
| Venues | `GET/POST /admin/venues` · `PUT /admin/venues/{id}` (creates a new version) · `POST /admin/venues/{id}/retire` |
| Engine | `GET /admin/engine/versions` · `PUT /admin/engine/active` (version for new races) · `GET/PUT /admin/engine/params/{version}` (draft params → new version) |
| Stable | `GET /admin/animals?status=` · `POST /admin/animals/{id}/retire` · `PUT /admin/stable/pool-size` |
| Seasons | `GET/POST /admin/seasons` · `PUT /admin/seasons/{id}` (only while UPCOMING) |
| Users | `GET /admin/users/{id}` · `GET /admin/users/{id}/ledger` · `POST /admin/users/{id}/adjust` (ledger `ADMIN_ADJUST` with reason) · `POST /admin/users/{id}/ban` |
| Ops | `GET /admin/dlq` · `POST /admin/dlq/{id}/replay` · `GET /admin/races/{id}/debug` (script access **only after FINISHED**) |

Rules: admins can't read a sealed script before `FINISHED`, the same
fairness rule as everyone else. Engine params and venues are versioned, never
edited in place.

## 5. API conventions

- Versioning: path prefix `/v1`; additive changes only within a version.
- Pagination: cursor-based, `?cursor=&limit=` (max 100) → `{ items, nextCursor }`.
- Errors: `{ code, message, details? }`, stable `code` enum.
- Time: RFC 3339 UTC; race-relative time in `tick`.
- Rate limits (per user, Redis token bucket): bets/cash-outs 10/s, reads 50/s;
  `429` with `Retry-After`.

### Idempotency keys

Required on `POST …/bets` and `POST …/cashout`.

- **Redis cache, TTL 2 h:** `idem:{userId}:{key}` → stored response. Fast
  retries return the original response.
- **Durable backstop:** the key is also stored on the bet / cash-out row with
  a unique constraint `(userId, idempotencyKey)`. It costs nothing and means a
  late retry can never double-bet, even after the Redis TTL.
- Inside the pipeline, Kafka consumers dedupe on `betId`, not the HTTP key. A
  message parked in the DLQ is investigated and replayed by `betId`, so the
  HTTP key's lifetime doesn't matter there.

## 6. Live stream (SSE): one stream per race

```
GET /v1/races/{raceId}/stream        (cookie auth; anonymous = public events only)
```

- **Always live, no catch-up.** There is no `Last-Event-ID` resume. On
  (re)connect the server first sends a `snapshot` event with the current state,
  then live events. The client drops whatever it had and jumps the three.js
  scene to the snapshot. Past ticks of a live race are never replayed to
  clients. That keeps everyone on the same clock as the live-betting
  acceptance delay.
- Prices are always "latest wins"; a reconnecting client never sees stale
  prices.
- Client reconnects with backoff (0.5 s, 1 s, 2 s, max 5 s); server sends a
  `ping` every 15 s.
- One Kafka-fed fan-out per race in the SSE Gateway; the user's own bet
  events are filtered per connection.

| Event | Data (JSON) | Audience |
|---|---|---|
| `snapshot` | `{ race, tick?, markets[], myBets[] }` | on connect |
| `race.lifecycle` | `{ status, at }` (OPEN→LOCKED→LIVE→FINISHED→SETTLED) | all |
| `race.tick` | `RaceTick` | all (LIVE) |
| `race.lap` | `{ lap, leaderEntrantId, standings[] }` | all |
| `market.opened` / `market.closed` / `market.suspended` / `market.resumed` | `{ marketId, … }` | all |
| `market.price` | `{ marketId, priceVersion, selections[{selectionId, price}] }` | all, ≤ 1 Hz |
| `market.resulted` | `{ marketId, winning[] }` | all |
| `bet.updated` | `Bet` | own bets only |
| `cashout.updated` | `{ betId, amount, quoteId, expiresAtTick }` | own open bets, ≤ 1 Hz |
| `ping` | `{}` | all |

## 7. Notifications: in-app inbox only

Scope: in-app only (no email, no push, no following). Race-starting alerts
are sent **only for races the user has bet on**.

```
GET  /v1/me/notifications?unread=&cursor=      → { items, nextCursor, unreadCount }
POST /v1/me/notifications/read                 { ids[] } | { all: true }
GET  /v1/me/notification-settings
PUT  /v1/me/notification-settings              { enabled: bool, types: { [type]: bool } }
```

- `enabled: false` turns everything off; per-type toggles otherwise
  (default all on).
- A Notification Service (TS) consumes `bet.events`, `race.lifecycle`, `season.events`
and leaderboard changes,
  checks settings, writes the inbox (Postgres, keyed by userId, 30-day
  retention) and pushes a `notification` event to any open race streams for
  that user, plus a badge count via `GET …?unread=true` polling.

| Type | Trigger |
|---|---|
| `RACE_STARTING` | a race you bet on starts in 2 min |
| `DAILY_REWARD_READY` | new UTC day, unclaimed |
| `LEADERBOARD_MOVE` | entered/left top 10 / top 100 |
| `SEASON_ENDING` | `endsAt − 24 h` |
| `SEASON_RESULT` | `SeasonEnded` (your final rank) |
| `BET_WON` / `BET_LOST` / `BET_VOID` | `BetSettled` |
| `BET_REJECTED` | live bet not accepted |
| `CASHOUT_DONE` / `CASHOUT_REJECTED` | cash-out result |
